# Semesta

Voxel action RPG 2.5D in the browser (the in-world town is **Anavela Universe**). three.js + Vite, vanilla JS ES modules. All pixel art (textures, sprites, icons) is generated procedurally via 16px canvas. Music & SFX are fully synthesized with WebAudio — no audio files. Exceptions: `logoasset/semesta.png` (logo) & `logoasset/nxrmascott.png` (mascot) imported by `src/ui/menu.js`, plus two Google webfonts (`Pixelify Sans` body via `--font-body`, `Silkscreen` display titles via `--font-display`, linked in index.html).

Art direction: cozy Stardew-Valley-ish palette (lush greens, warm earth, turquoise water), chibi big-head characters (NOT minecraft proportions), cute-critter enemies/NPCs/pets with big glossy pixel eyes (Pokemon / Pokopia / Animal Crossing energy).

## Running

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run preview
```

- **FACING CONVENTION** (get this wrong and everything moonwalks or crabs sideways): headings use `atan2(dx, dz)` and movement is `(sin d, cos d)`. A mesh whose forward is **+Z** (bunny, deer, turtle, every enemy) sets `rotation.y = d` directly. A mesh whose forward is **+X** (fish, gulls) needs `d - PI/2`, and on a `(cos a, sin a)` orbit it is `-a - PI/2`. Enemy `e.dir` used the maths convention (`cos`→x) while every `rotation.y` in the file used the other, and the WANDER branch never set a facing at all — which is why wandering monsters slid sideways
